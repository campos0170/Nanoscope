### S7-NOTCH1 - The Schmitt notch-line box has no line cap and silently truncates a long paste at 32,767 characters, mangling the trailing number into a frequency the user never typed — the sibling ML box on the same panel refuses above 32 lines

*Spectra (PSD/notch) and the voltage-dependence analyses*

**What the user sees.** Tick 'use explicit notch lines' on the Detection/Preprocess panel and paste a spreadsheet column of 10,923 frequencies. The QLineEdit keeps only its first 32,767 characters, so the box now holds 4,155 lines, and the cut lands mid-number: the user's 4,155th value 54.153999… becomes '54.' and parses to 54.0 Hz. No message says anything was dropped — the orange note under the box just reads 'Explicit spelling: 4155 line(s) — …'. Because 54.0 is already in the list at index 4000, the truncation MANUFACTURES a duplicate, and the next detection dies on 'ValueError: duplicate notch frequencies [54.0] Hz: the same line twice is a deeper, longer-ringing notch than the single line it looks like. List each frequency once.' — a refusal about a duplicate the user's paste did not contain. Without the collision the run simply proceeds with a notch line nobody asked for. And there is no cap at all: 4,155 lines cost 42 s per detection on the -600 mV file and ~3 minutes on the -500 mV file.

**Why it matters.** This is exactly the failure the ML tab's _ML_NOTCH_MAX_LINES = 32 exists to prevent — its own docstring names 'ONE accidental clipboard paste of a spreadsheet column into the freeform notch lines box' — and that guard was put on only one of the two boxes.
